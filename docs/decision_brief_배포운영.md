# 결정 1. 주 대상 독자는 누구인가

**왜 최상위 결정인가**: 독자가 정해져야 언어(한국어 vs 영어), 채널(카톡 vs 텔레그램 vs 왓츠앱 vs 이메일), 콘텐츠 형태가 전부 따라옴.

## 선택지

| 안 | 주 독자 | 언어 | 자연스러운 채널 |
|---|---|---|---|
| **1-A** | 한국 본사 임직원 | 한국어 | 이메일 / 카카오 / 텔레그램 |
| **1-B** | 해외 거점 현지 간부 | 영어 | 텔레그램 / 왓츠앱(현지 국민 메신저) |
| **1-C** | 양쪽 모두 | 한·영 | 채널 이원화 필요 |

## 트레이드오프

- **1-A (국내 본사)**: 이메일이 압도적으로 유리(무료·분량 무제한·규제 느슨). 카카오는 매일 자동 발송 시 유료(브랜드메시지)·마케팅 수신동의 필요.
- **1-B (해외 거점)**: 카카오 무용(현지 미사용). 왓츠앱·텔레그램 중심. 왓츠앱은 국가별 단가 상이(인도·동남아 저렴), 템플릿 승인·옵트인 필요. 텔레그램은 무료·무심사.
- **1-C (양쪽)**: 가장 완성형이나 언어 이원화·채널 이원화로 운영 부담 2배. UI는 이미 한·영 토글 지원하므로 브리핑 자체는 양쪽 대응 가능.

## 참고: 채널별 비용·제약 (합계 200명 가정, 매일 발송)

| 채널 | 건당 단가 | 월 비용(추정) | 규제 | 자동화 |
|---|---|---|---|---|
| 이메일 | ~0원 | 0~2만원 | 느슨 | 쉬움 |
| 텔레그램 | 무료 | **0원** | 거의 없음 | 쉬움(봇 API) |
| 카카오 브랜드메시지 | 23~25원 | 5~14만원 + 대행사 기본료 | 마케팅 동의·야간 제한·(광고)표기 | API(대행사) |
| 왓츠앱 Business | 국가별($0.01~0.12) | 상이 | 템플릿 승인·옵트인 | API(BSP) |

> 참고: 카카오는 매일 자동 push하려면 **브랜드메시지(유료)** 외 대안 없음. 무료 '채널 소식(포스트)'은 홈 게시 방식이라 도달 약하고 수동 발행이라 자동화 부적합.

**→ 논의 질문**: 이 서비스의 1차 독자는 국내 본사인가, 해외 거점인가? 유료 채널(카카오·왓츠앱) 비용을 감수할 의향이 있는가?

# 결정 3. 어디서 자동으로 돌릴 것인가 (운영 인프라)

**핵심 병목**: **Google News RSS가 클라우드/데이터센터 IP를 503으로 차단.** 현재 118피드 중 **76개(64%)가 Google News** 의존 → 수집이 사실상 맥북(가정용 IP)에 묶여 있음. 맥북은 상시 가동 불가, Oracle Cloud는 SSH 타임아웃 이슈.

## 선택지

| 안 | 방식 | 비용 | 무인 자동화 | 난이도 |
|---|---|---|---|---|
| **A** | 맥북 상시 자동화 (launchd/cron) | 0원 | △ (맥북 켜져 있어야) | 낮음 |
| **B** | 클라우드 + 레지덴셜 프록시 | 유료(월 수만원) | ✅ | 높음 |
| **C** | Google News → 직접 RSS 전환 (구조 개선) | 0원 | ✅ (D와 결합 시) | 중간(일회성 작업) |
| **D** | GitHub Actions 무료 cron | 0원 | ✅ (C 필수) | 낮음 |

## 트레이드오프

- **A (맥북)**: 가장 빠르게 자동화 달성, 무료. 단 맥북 절전/종료 시 실패 → `caffeinate`·전원 스케줄로 보완. **당장의 현실적 해법.**
- **B (프록시)**: 완전 무인이나 비용·취약성(프록시 IP도 차단됨). 최후 수단.
- **C (직접 RSS)**: 76개 Google News 피드를 매체 native RSS로 교체 → 클라우드에서도 503 없이 수집. 일회성 교체 작업 필요, 일부 현지 소형 매체는 native RSS 부재. **근본 해결.**
- **D (GitHub Actions)**: 서버 관리 불필요·무료. 단 Actions도 데이터센터 IP라 **C와 반드시 결합**해야 의미. Oracle Cloud SSH 고민 해소.

## 권장 로드맵 (단계적)

1. **단기 (당장)**: **A — 맥북 launchd 자동화.** 무료·수일 내 가능. "정기 자동화" 과제 즉시 해소. 맥북 절전만 관리.
2. **중기**: **C + D — 직접 RSS 전환 후 GitHub Actions 이전.** 맥북 의존 제거, 완전 무인 자동화. 소스 교체 작업 필요.
3. **B(프록시)**: 비용·취약성으로 비권장(백업 옵션).

**→ 논의 질문**: 더 큰 우려는 (a) 맥북 상시 가동 부담인가, (b) Oracle Cloud 불안정성인가? 단기 A로 가고 중기 C+D를 목표로 할지, 처음부터 C+D에 투자할지?

## 부록: 알려진 운영 이슈

- Google News RSS: 데이터센터 IP 503 (위 핵심 병목)
- Oracle Cloud SSH: 간헐적 타임아웃
- Reuters/Bloomberg/WSJ: 페이월 401/403 (본문 추출 ~50% 성공)

- ESG 카테고리: 기사 수 부족(3건/주) — 소스 보강 필요
