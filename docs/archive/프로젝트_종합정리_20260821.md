## 1. 프로젝트 개요

**「글로벌 One Team 뉴스데일리」** — KB금융 글로벌 11개 거점의 현지 뉴스를 매일 자동으로 수집·필터·AI 분석해, 본점·주재원·현지직원이 **같은 시각으로** 글로벌 금융 동향을 공유하는 데일리 뉴스 플랫폼. 그룹 글로벌 One Team Communication 강화가 목적.

- **주관**: 글로벌사업그룹 & 테크그룹 글로벌IT개발부 (사실상 1인 운영 체계)
- **확정안 반영**: 2026-07-13 사내 확정본 기준으로 정합화
- **핵심 파이프라인**: `수집 → 키워드필터 → 중복제거 → AI 1차관문 → 본문추출 → AI분석 → 번역 → 국가브리핑 → export → UI 배포`
- **배포 URL**: https://kb-global-daily.pages.dev (Cloudflare Pages)
- **GitHub**: https://github.com/lSusial/glb-one-teams.git

### 두 레포 관계

| 레포 | 역할 | 상태 |
|---|---|---|
| **glb-one-teams** (메인) | 수집 코어 + AI 레이어 + 정적 4탭 UI | **go-forward, 매일 운영 중** |
| glb-news-rss/prototype | 풀 파이프라인 + KB 대시보드(Streamlit, 로컬) | 참조·아카이브 (신규 작업 안 함) |

### 관리 11개 거점

GB 영국(런던·지점) · US 미국(뉴욕·지점) · HK 홍콩(지점) · CN 중국(베이징·법인) · JP 일본(도쿄·지점) · SG 싱가포르(지점) · IN 인도(구르구람·지점) · VN 베트남(하노이·법인) · MM 미얀마(양곤·사무소) · ID 인도네시아(자회사 KBI은행) · KH 캄보디아(자회사 프라삭은행)

- **소스 규모**: 88개 소스 / 106~118개 피드 (Google News RSS 우회 중심)
- 확정안 "8개 권역"은 샘플이었고 실제 레포는 11개 거점으로 확장 완료

## 2. 주요 구성 (아키텍처)

**설계 원칙**: 수집·필터·중복제거(AI 없음)가 코어 → 그 위에 **선택적 AI 레이어**(API 키 필요) → UI용 JSON export. AI 없이도 코어는 동작.

### 파이프라인 모듈

| 단계 | 모듈 | 역할 |
|---|---|---|
| 수집 | `collector.py` | RSS 병렬 수집, Google News 우회·실제 URL 해소 |
| 키워드필터+중복 | `keyword_filter.py` | 2단계 점수제 게이트(≥3), 제목 유사도 dedup |
| AI 1차 관문 | `llm_prefilter.py` | 무관·노이즈 keep/drop (Haiku, 저비용) |
| 본문 추출 | `fulltext.py` | trafilatura, Google뉴스 URL 해소 (무료) |
| AI 분석 | `llm_ranker.py` | ai_score·summary_ko·topics·kb_implication 생성 |
| 번역 | `llm_translate.py` | ACTIVE분 한국어 / EN canonical 폴백 |
| 국가 브리핑 | `briefing.py` | 국가별 일일 브리핑 (11~12개국) |
| 프로바이더 | `llm_provider.py` | Anthropic/OpenAI/Stub 추상화 + Batches API(50%↓) |
| export | `export_json.py` | DB → data/export/*.json |
| UI | `web/*.html` | 정적 4탭 SPA |

- **공통 인프라**: `config.py`(임계값·모델 단일출처), `db.py`(SQLite, 멱등 마이그레이션), `schema.sql`
- **분류 체계**: `taxonomy.yaml` 주제코드 6종 — MARKET(경제)·BANKING(금융산업)·DIGITAL(디지털)·RISK(규제·리스크)·GEO(지정학)·ESG
- **비용 설계**: 모델=Haiku, Message Batches API(50% 할인) 기본, `--days 2` 물량 제한, ACTIVE 임계=55

### 화면 구성 (4탭 정적 SPA)

| 탭 | 파일 | 내용 |
|---|---|---|
| ① Global Pulse | brief.html | 카테고리 온도계(5) + 오늘의 핵심뉴스(중요도순) |
| ② 현지언론 | countries.html | 거점 선택 → 일일 브리핑 + 기사 피드(카테고리 필터) |
| ③ 주간 리포트 | weekly.html | 국가별 주간 상위 기사 |
| ④ 이슈 트래커 | topics.html | 카테고리 탭(경제/금융/디지털/규제·리스크/지정학/ESG) |

> 기획상 6탭(+규제·금융기관, +참여)이었으나 규제는 TopicWatch로 흡수, 참여형은 범위 제외 → 현재 4탭으로 정리.

### 평가 프레임워크 (eval/)

- `eval_set_v2.jsonl` — 149건, grade 0~3, 11개 거점 균형
- prefilter 최종 성능: **P=0.739 · R=0.680 · F1=0.708** (개선 전 F1 0.542 → 0.708)
- `run_eval.py --mode prefilter|ranker`

## 4. Risk (리스크)

### 운영 인프라 — 최대 병목

- **Google News RSS가 클라우드/데이터센터 IP를 503 차단.** 현재 118피드 중 **76개(64%)가 Google News 의존** → 수집이 사실상 맥북(가정용 IP)에 묶임. 맥북은 상시 가동 불가.
- **Oracle Cloud 서버 SSH 간헐적 타임아웃** → 서버 자동화의 걸림돌.
- 최근 gnews 커버리지 테스트(8/20): 목표 주요 매체 상당수 미회수(GB 0/3, US·HK 1/3 등) — 구글뉴스 쿼리가 스포츠·연예 등 노이즈를 다수 반환.

### 수집 품질

- **Reuters/Bloomberg/WSJ 페이월**(401/403) → 본문 추출 **약 50% 성공률**
- **RTHK 피드 XML 파싱 오류**(SAXParseException) — 수집 실패
- **ESG 카테고리 기사 부족**(3건/주) — 소스 보강 필요
- DB integrity check 실패 이력(인덱스 손상) → `REINDEX idx_articles_dedup`으로 복구 절차 존재

### 즉시 선결 과제

- **`ANTHROPIC_API_KEY` 무효 상태** → 최근분 AI 단계(prefilter·rank) 실행 막힘. **키 교체 필요** (결정이 아니라 즉시 조치)

### 사업·일정

- **1인 운영 체계** — 확대·Grand Open 세부 일정 미확정
- Grand Open 전제조건(메신저/Pages 배포, 한·영 토글 번역)이 미구현 → Pilot(STAGE 01~02) 내 확보 필요

## 6. 운영 방법 (참고)

```bash
# 일일 수집 + AI + 배포 (맥북)
python main.py run              # fetch → filter → dedup
python main.py ai --days 2      # prefilter → fulltext → rank → translate → brief (배치, ~10분)
python main.py export           # JSON 생성
wrangler pages deploy data/export --project-name kb-global-daily --commit-dirty=true

# 서버 동기화
./sync_to_server.sh --collect   # 수집 후 전송

# 평가
python main.py eval --mode prefilter|ranker
```
