## Phase 2 (AI) — 준비·실행

> AI 레이어는 `ANTHROPIC_API_KEY` 필요. 산출: `ai_score`(0~100)·`summary_ko`·`topics`(taxonomy)·`kb_implication`.
> 배선은 `LLM_PROVIDER=stub`으로 검증 완료(키 없이). 실제 호출은 아래.

### 0. 레거시 AI 값 초기화 (최초 1회 — 프로토타입 데이터 재조정)

구 프로토타입이 남긴 값(스케일·어휘 상이)을 초기화해야 새 파이프라인에 편입된다.

```bash
sqlite3 data/news.db <<'SQL'
-- 구 프리필터 어휘(passed/rejected) → NULL (재프리필터 대상화)
UPDATE articles_raw SET llm_prefilter=NULL, llm_reject_reason=NULL
 WHERE llm_prefilter IN ('passed','rejected');
-- 구 1~5 스케일 랭킹 → NULL (0~100로 재랭킹, taxonomy·kb_implication 재생성)
UPDATE articles_raw
   SET ai_score=NULL, summary_ko=NULL, topics=NULL, kb_implication=NULL, ai_model=NULL
 WHERE ai_model='claude-haiku-4-5-20251001';
SQL
```

### 1. 배선 검증 (키 없이 — 선택)

```bash
LLM_PROVIDER=stub python main.py ai      # 더미 산출물로 흐름만 확인(비용 0)
```

### 2. 실제 실행 — 최근치만 (권장, 비용 절감)

데일리 제품엔 전체 히스토리가 아니라 **최근 며칠치만** 필요하다. `--days`로 범위를 좁힌다(전체 9천여 건 → 최근 7일 ~900건, 약 90%↓).

```bash
export ANTHROPIC_API_KEY=sk-ant-...
python main.py prefilter --days 7    # 최근 7일만 keep/drop (Haiku, 저비용)
python main.py rank --days 7         # 최근 7일 keep 기사 분석 (Sonnet)
python main.py list --limit 10       # 결과 확인 (ai_score 0~100)
python main.py brief                 # 국가별 브리핑
python main.py export                # ACTIVE 모드 — 실제 AI 큐레이션
python main.py admin
```

> `--days` 미지정 시 **전체 백로그**를 처리한다(초기 1회 전량 큐레이션이 필요할 때만). 1회에 `PREFILTER_LIMIT`(300)/`RANK_LIMIT`(150)씩 처리하므로 전량은 반복 실행이 필요하고 Sonnet 호출이 그만큼 많다 → 시간·비용↑.

### 3. 일상 운영 (매일)

매일 수집 후 신규분만:
```bash
python main.py run                    # 수집·필터·중복
python main.py ai --days 2            # 최근 2일 prefilter→rank→brief 일괄
python main.py export && python main.py admin
```

> 모델 분리(`config.py`): prefilter=Haiku(저비용), rank/brief=Sonnet.

## 문제 해결

| 증상 | 조치 |
|---|---|
| `ModuleNotFoundError` | `.venv` 활성화 / `pip install -r requirements.txt` |
| 피드 다수 503·빈 응답 | 서버에서 실행 중일 가능성 → 맥북에서 실행 |
| `export`가 0건 | 정상(ACTIVE는 AI 점수 필요). `export --passed` 사용 |
| RTHK 피드 오류 | 알려진 이슈(피드 자체 XML 오류), 무시 |
